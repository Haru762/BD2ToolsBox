## 1. 本轮做了什么

- **引入 kotlinx.serialization**（T35 计划要求的运行时）：
  - `gradle/libs.versions.toml`：`serialization = "1.9.0"`、
    `kotlinx-serialization-json` 库、`kotlin-serialization` 插件（版本随 `kotlin = 2.2.20`）；
  - `app/build.gradle.kts`：插件 alias + `implementation(libs.kotlinx.serialization.json)`。
  - 依赖与插件均在本地 Gradle 缓存中（T13 探针已验证该组合），offline 构建可解析。
- 新增 `core/storage/dto/StoredInstalledMod.kt`：装入账本记录的持久化 DTO，
  字段名用 `@SerialName` 与 Gson 时代**逐字相同**，可选字段带默认值。
- 新增 `core/storage/LegacyJsonReader.kt`：旧格式账本 JSON 的兼容读取：
  - 顶层必须对象 + 数字型 `schemaVersion`（不认识 → Corrupt）；
  - `records` 必须对象；条目缺必需字段/类型不符 → 整次 Corrupt（**不静默补默认**）；
  - 未知字段忽略；可选字段缺失用默认；空文本 → Empty；截断/非对象 → Corrupt。
  - 只读，不改文件。
- 新增 `JsonMigrationTest`（13）。

### 1.2 第二增量：`InstalledLedgerStore` 读写改走 kotlinx.serialization

- `parse`：Gson `JsonParser`/`TypeToken` → kotlinx `Json.parseToJsonElement`；
  **逐条解码**（缺必需字段/类型不符时错误里点出是哪一条记录）；v0 legacy 裸表仍支持；
  主键必须等于 `modUri` 的校验保留。
- `encode`：Gson `toJsonTree` → kotlinx `buildJsonObject` + `encodeToJsonElement`；
  顶层 `{"schemaVersion":1,"records":{...}}` 形状与字段名不变。
- 结果：`InstalledLedgerStoreTest` **24/24**、全量 JVM **659/0/0/0** 全绿。
  （过程中真实修过一处：首版整表一次解码，导致「损坏原因要点出是哪一条记录」的
  既有断言失败；改为逐条解码后错误里带上了 key。）
