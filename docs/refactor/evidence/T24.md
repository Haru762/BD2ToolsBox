## 1. 本轮做了什么

### 1.1 目标筛选与空间计划同源（修掉一处真实不一致）

- 新增 `feature/preview/PrepackExecutor.kt`：
  - `selectTargets(mods)`：有效缓存跳过；负缓存（`isKnownNoPreview`）也跳过；
    非 `CONVERTED_BUNDLE`、缺 `targetHash`/`convertedHashDir` 的条目忽略。
  - `plan(mods, freeBytes)`：`todo` 与 `selectTargets` 同源。
- **修掉的真实不一致**：改动前 `MainViewModel.preparePrepack` 的计划只按
  `isValid` 统计 `todo`（`todo = converted.size - cached`），而 `startPrepack`
  的目标筛选还会跳过负缓存。于是「解包成功但无预览价值」的产物被算进计划待办数，
  用户看到的 todo 偏大。现在 `plan.todo == selectTargets(...).size`，由
  `PrepackExecutorTest.planTodoMatchesSelectTargets` 固定。
- 缓存 key 维度未改：`<bundleName>/<hashDir>_<size>`（bundle 名是目录层，hash 与
  源大小进槽名），`distinctVariantsOfTheSameBundleAreSeparateTargets` 固定
  「同 bundle 不同 size 各自成槽」。
- `MainViewModel.preparePrepack` / `startPrepack` 改为委托 `PrepackExecutor`；
  构造新增 `prepackExecutor` 注入。膨胀比、空间限制、负缓存语义保持不变。

### 1.2 测试接线

## 2. 明确未完成（不勾 DONE 的原因）

- **静态 `pendingTargets` 未任务 ID 化**：`PrepackService.companion` 仍用
  `@Volatile private var pendingTargets: List<Target>?` 作为进程内交接。计划要求
  「去除静态 pendingTargets/全局 progress 作为唯一任务来源；Service 通过任务 ID
  取得经过验证的参数，缺参数重建不能显示已完成」——本轮**没有**接入 T21 的
  `OperationStateStore`，Service 仍按裸列表启动。
  （事实补充：`START_NOT_STICKY` + 同进程，进程被杀后服务不会被重启，
  所以「缺参数却显示已完成」在当前实现下不可达；但「唯一任务来源」这条仍不满足。）
- **PrepackService 仍未驱动 `PrepackExecutor`**：Service 内仍是自己的解包循环；
  `PrepackExecutor` 目前只被 ViewModel 用于筛选/计划，没有成为 Service 的执行入口。
- **`PrepackCacheIntegrationTest` 未改**：计划要求它参与「真实生产缓存文件」的
  集成验证，本轮未触碰。
- **`PreviewCacheRepository` 未改**：缓存分槽/负缓存/代数戳语义未动，因此没有
  需要修改的点；但这不构成「已重新验证」。
- **设备验收 NOT_RUN**：`adb devices` 仅 `127.0.0.1:15557 offline`，无就绪设备。
