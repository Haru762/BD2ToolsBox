## 2. 探针工程（已纳入版本控制）

`tools/compat-probe/`：独立 Gradle 根，自带 wrapper（Gradle 8.13，带 `distributionSha256Sum`）。`gradle-wrapper.jar` 复制自生产仓库（SHA-256 `7d3a4ac4…6172`）。生产 `settings.gradle.kts` 没有 include 它。

- 只有 `:app` 一个模块，也是唯一应用 Chaquopy 的模块。
- 覆盖面：
  - `@HiltAndroidApp` Application；
  - `@Singleton` 构造注入 `@ApplicationContext`；
  - `@Module`/`@Provides`；
  - `@EntryPoint`；
  - `@AndroidEntryPoint` Activity；
  - `@HiltViewModel` + Compose `hiltViewModel()`；
  - `@Serializable` DTO：固定 `@SerialName`、默认值、未知字段；
  - Chaquopy 调用 `lz4`/`Pillow` native wheel，并读取 `AndroidPlatform.ABI`；
  - AboutLibraries 自动生成 `R.raw.aboutlibraries`。
- `CompatibilitySmokeTest`（androidTest，5 项）针对 debug。
- minified release 由 App 内 `MainActivity --ez selfCheck true` 验证同样的 5 项，不经过测试包（原因见 §4）。
- `SerializationJvmTest`：JVM 单测，确认 serialization 插件生成了 serializer。
- 本机输入：`tools/compat-probe/local.properties`（被 `.gitignore` 忽略，只含 `sdk.dir` 与 `chaquopy.python`）。

5 项检查的实际输出：
- hilt：entryPoint、singleton、activity 注入、viewModel 都 OK。Activity 注入的 repository 与 EntryPoint 返回的是同一实例。
- serialization：`{"schemaVersion":1,"mods":["char000104","char000201"],"savedAt":1789992348967}`；未知字段被忽略，缺失字段取默认值。
- python：`3.8|x86_64|lz4-ok|PIL-9.2.0`，ABI 与 `nativeLibraryDir` 一致。

**失败记录（保留）：**
- 第一次尝试 minified release 时用 `testBuildType=release` 构建测试包。测试包自身 R8 先报缺 errorprone 注解；加上 dontwarn 后，在 Application 创建阶段报 `NoSuchMethodError: No static method e(Ljava/lang/Object;Ljava/lang/String;)V in class Lv1/f`。
- 原因是测试包按 release mapping 调用了已被内联的方法，与 T04（`release-probe/build.gradle.kts` 顶部）记录的问题相同，不是依赖组合不兼容。
- 这条路线已撤销：`testBuildType` 属性和测试专用 proguard 文件都已删除，改用 App 内的 selfCheck。原始 logcat 在 `local/t13/device-x64/release-logcat.txt`。
- 另有一次模拟器在运行中自行退出，导致一轮 instrument 无输出（`local/t13/emulator.log`）。重启后重跑的结果以上表为准。

## 7. 2026-09-26 原生 arm64 真机

用户授权在个人手机安装隔离探针包（`com.bd2toolsbox.compat` / `.test`），测完卸载；不触碰用户的 `com.bd2toolsbox`、游戏与 Shizuku。

- 安装的是 §5 中重建后的同一批 APK（哈希不变）；`primaryCpuAbi=arm64-v8a`。

| 构建 | 方式 | 结果 | 原始输出 |
|---|---|---|---|

- logcat 中 `Fatal signal`/`SIGSEGV`/`SIGABRT`/`FORTIFY` 为 0。
- **未通过的一项（如实保留）：** `CompatibilitySmokeTest#hiltActivityInjectionAndViewModel` 在该手机上两次都挂起，没有返回结果。第一次挂起时手机熄屏锁屏。第二次屏幕已解锁，logcat 仍记录 `ActivityStarterImpl: MIUILOG- Permission Denied Activity ... pkg : com.bd2toolsbox.compat`，`ActivityScenario` 等不到 Activity 进入 RESUMED 状态。这是 MIUI/HyperOS 拦截了由 instrumentation 进程发起的 Activity 启动，不是依赖组合的问题：

  - 用 `am start` 从 shell 冷启动同一 Activity 后，Activity 注入与 Compose `hiltViewModel` 在该设备上的 debug 包和 minified release 包中都 PASS。
  - 挂起时的 logcat 保存在 `local/t13/device-arm64/debug-logcat-hang.txt` 与 `debug-logcat.txt`。
- 收尾：两个探针包都已卸载。用户 `com.bd2toolsbox` 前后 `versionCode=17`、`lastUpdateTime=2026-09-14 12:32:19` 不变（`before|after-bd2toolsbox.txt`）。
