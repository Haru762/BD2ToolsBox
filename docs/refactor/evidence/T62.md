## 1. 本轮做了什么

- 新增 `core/storage/MediaExclusionManager.kt`（纯逻辑 + 普通文件系统）：
  - `MARKER_NAME = ".nomedia"`；`isMarkerName` **只认精确同名**（`.nomedia.txt`/`.nomedia.bin` 不算）；
  - `isMixedUseRoot`：DCIM / Pictures / Movies / Download(s) / Documents / 存储根等
    **拒绝默认加标记**（大小写不敏感、去空白）；
  - `ensureMarker(dir, refuseMixedUseRoot = true)`：不存在→Failed、混合用途根→Rejected、
    已有同名普通文件→AlreadyPresent（**不覆盖不删除**）、否则创建空普通文件→Created；
    并发 `createNewFile()` 返回 false 时按已存在处理；
  - `verifyProviderName(actualName)`：provider 返回的实际名称必须恰好是 `.nomedia`；
  - `shouldSkipInModScan(name)`：MOD 枚举/签名/重打包输入应跳过的条目（仅标记自身）。
- 新增 `MediaExclusionManagerTest`（10，JVM）。
- Python：`repacker/repacker.py` 新增 `should_ignore_entry`（`.nomedia`/`.modfile`）并接入
  `_build_file_index`（枚举时跳过）；新增 `tests/test_nomedia_ignored.py`（9）。
- Kotlin 侧 MOD 枚举：`ModRepository.shouldIgnoreModEntry` 与
  `MainViewModel.shouldIgnoreModEntry` 追加 `MediaExclusionManager.shouldSkipInModScan`，
  使 `.nomedia` 不进入 MOD 识别、来源内容签名与重打包输入。
