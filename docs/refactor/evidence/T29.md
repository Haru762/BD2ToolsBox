## 2. 修掉的缺陷：清缓存失败却显示成 0

与 T44 修过的备份清空**完全同类**，这次在预览缓存与 Spine 运行时上：

```kotlin
// 旧
fun clearAll() { root().deleteRecursively() }          // 返回 Unit
...
previewCacheRepository.clearAll()
_previewCacheUsage.value = 0L to 0                     // 无条件置 0
```

删除失败（权限、文件被占、外部存储卸载）时界面显示「已清空」，磁盘上一个字节没少。
计划明确要求「清缓存失败准确反馈，不能把未成功删除的空间直接显示为0」。

改法（两个仓库一起）：

| 改动 | 说明 |
|---|---|
| `PreviewCacheRepository.clearAll(): PurgeOutcome` | 逐顶层条目删并统计成功/失败；剩余量**重新测量** |
| `SpineRuntimeRepository.clear(): PurgeOutcome` | 同上；旧实现 `forEach { it.delete() }` 连返回值都丢掉 |
| `MainViewModel.clearPreviewCache()` | 用 `outcome.remainingBytes to remainingCount` 更新用量，不再写死 0；结果存进 `previewPurgeResult` |
| `MainViewModel.clearSpineRuntime()` | 同上 |
| `core/model/CachePurge.kt`（新增） | 结果文案：失败时**必须**说出实际占用；`needsAttention()` 给界面判断 |
| `WorkbenchSheet` | 失败/部分成功时在缓存行下面显示真实原因与剩余占用，带「知道了」 |

复用 T44 建的 `PurgeOutcome`（`attempted/deleted/failed/remainingCount/remainingBytes`），
但文案单独一份 —— 「已清空 3 份原版备份」出现在预览缓存上说不过去。

### 2.1 与活跃任务互斥

```kotlin
fun previewCacheBlocker(): String? {
    val busy = installJobs.value.isNotEmpty() ||
        prepackProgress.value != null ||

    return if (busy) "有任务正在进行（装入/预解包/预览），先等它收尾再清缓存。" else null

```

### 3.1 测试里踩到的一个坑

第一版用 `File.setWritable(false)` 制造删除失败，失败时用
`org.junit.Assume.assumeTrue(false)` 跳过 —— **本仓的门禁把 assumption failure
（status -4）当成失败**（「skip 不是通过」）。而且这台设备的文件系统
根本不理会 `setWritable(false)`，照样删得掉。

所以那条用例改成断言「剩余量必须等于**重新测量**出来的磁盘状态」——
绕开仓储直接往缓存根目录塞一个它不认识的条目，如果实现是「删过了就当 0」就会露馅。
这比依赖一个造不出来的失败更可靠。
