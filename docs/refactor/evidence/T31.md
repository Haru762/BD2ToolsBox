## 1. 本轮做了什么

- 新增 `feature/cdk/RedeemSummary.kt`：
  - `RedeemDisposition` 六态：SUCCESS / ALREADY_REDEEMED / TERMINAL_FAILURE /
    RETRYABLE_FAILURE / NOT_ATTEMPTED / UNKNOWN；
  - `dispositionOf(RedeemOutcome)`：`success`→SUCCESS，`AlreadyUsed`→ALREADY_REDEEMED，
    `UnknownResult`→UNKNOWN，非可重试→TERMINAL_FAILURE，其余→RETRYABLE_FAILURE；
  - `RedeemSummary`：`successCount` / `alreadyRedeemedCount` / `terminalFailureCount` /
    `pendingCount` / `unknownCount` + `total` / `settled` / `allRedeemed`；
  - `summarizeRedemption` / `summarizeOutcomes`。
- 新增 `feature/cdk/CdkUiState.kt`：兑换页状态（账号、条目、busy、settledCodes、history、lastSummary）。
- 新增 `feature/cdk/CdkViewModel.kt`：账号/历史/结算集合 + `redeemAll`/`redeemOne`，
  批量与单码共用一把 `Mutex`（屏幕重组/旋转/重复点击不双发）；仓储异常如实进状态并上抛。
- `Bd2RedeemRepository.parseOutcome`：解析失败分支补 `errorCode = "UnknownResult"`，
  让「响应到了但结果未知」可被区分（原先只有一句文案）。
- 新增 `CdkViewModelTest`（9）。

关键语义（验收项）：
- **空集合不算「全部兑换成功」**：`allRedeemed` 与 `settled` 都要求 `total > 0`；
- **全是终局失败可标为已处理**（`settled == true`），但 `successCount` 必须为 0；
- 未知/可重试/未处理都阻止 `settled`。
