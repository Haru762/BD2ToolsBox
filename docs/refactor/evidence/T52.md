## 2. 逐条复核（要点，完整表见 r8-rules.md §2）

- **删** `-keep class com.chaquo.python.** { *; }` 与 `…runtime.**`：Chaquopy 16.1.0
  自己接入 `build/python/proguard-rules.pro`（T49 已在 `configuration.txt` 的 section 头
  核对过），属重复声明。
- **删** `-keep class com.bd2toolsbox.data.model.** { *; }` 与
  `-keep class com.bd2toolsbox.core.storage.** { *; }`：两条的理由都是
  「Gson 按字段名读写」，而 T35 已把序列化全部迁到 kotlinx.serialization
  （键名是 `@SerialName` 字符串常量、`$$serializer` 静态引用）。这是本轮的主要收窄。
- **保留** `PythonRuntime.ensureStarted`（release-probe 跨包反射）与
  `ShizukuFileService { *; }`（Shizuku 按组件名绑定；T19 真实授权未验，不猜着收窄）。
- **升级** `SnapshotV1` 的字段规则为 `-keep`：实测发现类名是载重的
  （见 §4 的 `SnapshotV1 class is renamed in mapping.txt`）。
- **新增** 一组精确的 `ModSnapshotStore` / `PendingWrite` / `SnapshotLoad($*)` /
  `SnapshotCommit($*)` / `SnapshotEntry` 规则 —— 删包级 keep 后 release-probe 跨包反射
  报 `ClassNotFoundException`，这是真实的动态入口，不是「为了过测试」。
- 未使用「保留所有业务类」「忽略所有警告」「-dontoptimize」。

## 4. 验证

### 4.1 构建

- `Invoke-Bd2Gradle --offline :app:assembleArm64Release`（带证据规则）→ **BUILD SUCCESSFUL**，exit 0。
- `Test-Bd2ReleaseSmoke -Case 'snapshot-compatibility' -Abi 'x86_64'`
  → **ReleaseSmoke [snapshot-compatibility/x86_64] 127.0.0.1:16384 -> PASS**，exit 0。
  该 case 在**真实 minified release** 上做跨进程 `ModSnapshotStore`
  `load`/`capture`/`commit` 契约、冻结夹具逐字段比对、mapping.txt 的 SnapshotV1 保名闸、
  以及 UI 冷启动。

### 4.2 审计

- `--expected-abi` 两个包 **exit 0 / findings 0 / abiProblems 0**。
- DEX 里 `@SerialName` 键名常量仍在（`schemaVersion`/`savedAt`/`sourceDirs`/
  `installedAt`/`bundleName`/`revision`/`bundle_aliases` 逐项为 True）。
- `$$serializer` 类仍在（`StoredInstalledMod$$serializer -> R1.a`、
  `ModSnapshotStore$SnapshotV1$$serializer -> Q1.K`、`StoredJournalEntry$$serializer -> R1.d`）。

### 4.3 测试发现并修复的真实问题

首轮删掉包级 keep 后，`snapshot-compatibility` 依次暴露两个**真实**动态入口：
1. `ClassNotFoundException: com.bd2toolsbox.core.storage.ModSnapshotStore`
   （release-probe 跨包反射）→ 补精确 keep；
2. `SnapshotV1 class is renamed in mapping.txt`
   （T10 的 mapping 闸）→ 把 `-keepclassmembers` 升级为 `-keep`。
两处都不是测试写法问题。
