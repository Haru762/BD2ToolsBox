## 2. 已实现的内核

- Hilt `@Singleton` 状态源：按 ID 保存目标参数及状态，提交时复制参数，状态对外仅提供 `StateFlow`。没有静态 pending 字段，不保存 UI、执行闭包或私有逃逸 scope。
- 接纳、领取、状态更新和资源释放共用一把锁；同一 ID 不覆盖已有结果，同 bundle 操作拒绝冲突，清缓存采用保守的全局排他。
- 宿主在自己的 scope 中调用 `execute(id)`，执行器与其子协程收尾后才释放参数和目标占用。取消观察者不影响宿主任务；重复服务投递不重复领取。
- 准备、运行、细分解析/枚举、提交及五类终态分开。已提交、失败、跳过逐目标登记；未报告完所有目标不能判成功或伪报 100%。
- 取消是请求。提交临界区使用 `NonCancellable`，同时阻止引擎回调/checkpoint 在已进入的提交中立即取消；已提交事实保全后再标取消/中断。
- 启动前台服务被拒可以结束尚未领取的任务；迟到的拒绝不能结束运行中任务。确认终态后可释放结果。
- 执行句柄与本次参数实例绑定，过期回调不能借复用的 ID 修改新任务。致命引擎异常保留事实并继续抛给宿主，不在 finally 中发布成功。

**尚未接线：** 真实安装/卸载、扫描、预解包参数及对应 Service 调用属于 T22–T24；现有磁盘 journal 与任务 ID 的接线、进程重建属于 T25。当前内存状态不能作为恢复凭据，不据此声称页面退出后的现有生产流程已经修好。
