## 1. 本轮做了什么

- `feature/cdk/RedeemSummary.kt`：
  - `RedeemSummary.canRetry`：**由结果性质决定**（只有待处理/结果未知才可重试），
    不看「按钮会不会误导」；
  - `RedeemSummary.resultLabel()`：**成功标签只在真有成功时出现**；
    未知优先于失败与待重试（有未知就不能声称失败或成功）；
    全终局失败 → 「兑换失败」，空集合 → 「未处理」；
  - `AccountRedeemResult` / `BatchRedeemSummary`（账号维度汇总、`aggregate`、
    `retryableAccounts`、`canRetry`）；汇总**不覆盖历史**；
  - `AccountRedeemResult.describe()`：账号 + 数量 + 原因（全失败文案不含「成功」）。
- 新增 `feature/cdk/CdkResultPresentation.kt`：
  - `toneFor(summary)`：失败→ERROR、未知→INFO、待重试→WARNING、空→NEUTRAL、
    已兑换→SUCCESS、混合→WARNING；
  - `RedeemAccountResultRow`（复用 T41 `StatusBadge`，语义名「兑换结果：<describe>」）；
  - `batchResultText(batch)`：全失败说明原因与下一步（可重试项保留），不涂成成功。
- 新增 JVM 测试 `feature/cdk/RedeemSummaryTest`（10）与设备测试
  `ui/CdkResultPresentationTest`（5）。

## 3. 测试发现并修复的真实问题

首轮 JVM 运行 1 个 FAILED：`unknownCount > 0` 的纯未知集合被标成「待重试」而不是
「结果未知」。修复：`resultLabel()` 中**未知优先**（有未知就不能声称失败或成功）。
这是真实语义错误，不是测试写法问题。
