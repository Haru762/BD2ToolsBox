## 1. 本轮做了什么

- 新增 `feature/settings/BackupPurgeConfirmation.kt`：
  - `BackupPurge.consequence(count, humanBytes)`：确认前说清**数量、空间、后果**
    （失去本地原版恢复资源、不可撤销）；
  - `DIALOG_TITLE = "清空原版备份？"` 与 `CONFIRM_LABEL = "清空原版备份"`：
    按钮写明动作，不用泛化的「确定」；标题与按钮**不同名**（见 §3 的修复）；
  - `fingerprint(backups)` + `revalidate(confirmed, current)`：确认时冻结目标指纹，
    执行前比对；集合变了返回 `Changed(currentCount)`，**必须重新确认**，
    不删确认之后新产生的备份；
  - `outcome(attempted, deleted, remainingCount, remainingBytes)` 与
    `resultText(...)`：成功/部分成功/全失败三种文案，剩余量用**重新统计**的值，
    删除失败时**不把数量/空间置 0**；
  - `blockedByActiveTask(activeTaskId)`：与活跃安装/卸载/预解包互斥。
- 新增设备测试 `ui/DestructiveActionConfirmationTest`（8）。

## 3. 测试发现并修复的真实问题

首轮设备运行 **FAILED（3 个用例）**：`onNodeWithText("清空原版备份")` 找到 **2 个节点** ——
