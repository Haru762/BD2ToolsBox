## 2. PyObject 封闭 + 类型化边界

- 解码只依赖中性接口 `PyCell`（`asBool/asInt/asLong/asText/asMap`）；`PyObject` 只在 `ChaquopyPyCaller`（把 `main_script` 返回的每个单元包成 `PyObjectCell`）里出现。ViewModel/UI 拿到的永远是 `Pair`/`Triple`/`JSONObject`/`String`。
- 桥接错误兜成各入口约定失败值并保留诊断（`printStackTrace`）。
- **协程取消不被吞：** `callMain` 先 `catch (CancellationException) { throw e }` 再 `catch (Exception)`——取消照常向上传播，不记成「未知错误」。`EngineProtocolTest#cancellationExceptionIsRethrownNotSwallowed` 钉住。
- **生命周期：** 引擎不启动 Python；解释器仍由 `PythonRuntime.ensureStarted` 懒启动、全进程一次。可取消入口仅 `unpackBundle`（回调返 true 请求取消），其余为不可中断的整段调用（注释已写明）。

## 3. 单一实例（无双桥）

`EngineModule` 提供唯一 `@Singleton ModEngine`，构造时 `ModEngine.install(it)` 注册为进程级默认。Hilt 注入方（MainViewModel、PrepackService）与静态调用方（ShizukuManager/BundleNameResolver/ModRepository 经 `ModEngine.get()`）拿到**同一个** `ChaquopyModEngine`。`get()` 的兜底（未安装时新建）仅用于测试/极早期调用，行为一致。**这是明确标注的 T20 清理项**——T19 把 Shizuku 隔离后，这些静态调用方改注入，删除 `get()/install()`。
