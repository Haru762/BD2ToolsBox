## 2. 实测


`tests=1456` = 728 个 JVM 用例 × 2 个 flavor 变体。

### 2.2 判据不放宽

- `Test-Bd2UnitAll` 与 `Test-Bd2Unit` 同判据：跑前把 test-results 移入回收站、
  跑后必须读到 `TEST-*.xml`、**failures / errors / skipped 任一非零即失败**、零用例即失败。
- Python 侧逐个文件走 `Test-Bd2Python`（含它自己的 skip 判定）。
- 静态审计用真实产物：`check_architecture.py`、`audit_apk_size.py`
  （`--expected-abi` + 资源名 + DEX 键名）、`audit_native_abi.py`。
- **设备测试不隐式执行**：`LocalAll` 不调用任何设备函数。

### 2.3 实现过程中修掉的真实缺陷

1. **`LocalAll` 原先逐类调 `Test-Bd2Unit`** —— 每个类一次 Gradle，66 个类把同一个任务重跑
   几十次。新增 `Test-Bd2UnitAll`：每个 flavor 一次 Gradle + 一次 XML 聚合，判据不变。
   逐类入口保留（各任务要按类引用具体证据）。
2. **`Read-Bd2UnitXml` 的返回形状用错**：它是**扁平**聚合
   （`tests`/`failures`/`errors`/`skipped` 直接在顶层），我按 `$summary.counts[...]` 取，
   直接 `NullArray` 抛错。已按真实形状取。

### 2.4 基线清单核对（T60 明确要求的那一步）

新增 `tools/verify_manifests.py` 并接进 `LocalAll` 第 5 步：

```
manifests: checked=16 mismatched=0 missing=0
```

16 条全部对上：`historical-0.2.16`（2 APK + mapping）、`rebuilt-original`
（3 APK + mapping + output-metadata）、`pre-shrink`（2 APK + 2 mapping）、
两个 fixture 输入、两份 T48 审计报告。**唯一基线一个都没被动过。**

**过程中修掉工具自己的一个 bug**：`t48Freeze.toolRun[]` 同时有 `apk` 与 `output`，
而那里的 `sha256` 指的是**输出报告**的哈希。我最初按 `apk` 优先取路径，拿 APK 的字节
去比报告的哈希，报出两个**假的**「哈希不符」。已把 `output` 提到 `apk` 前面，
并加了针对性回归用例。
