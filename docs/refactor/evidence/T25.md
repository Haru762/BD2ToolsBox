## 2. 真实「杀进程再启动」（本轮补上的那一项）

### 2.1 为什么以前没做

`ProcessDeathRecoveryTest` 原来写着「真实『杀进程再启动』的循环不在本类里：
instrumentation 无法杀掉自己的进程后继续执行」。

**那不是做不到，只是没做**：把过程拆成三次 `am instrument`、阶段之间 `am force-stop`
就行 —— `Invoke-Bd2SnapshotPhases` 早就是这个手法。

### 2.2 做法

`Test-Bd2JournalRecovery` 依次：

1. `JournalRestartPhaseTest#writeInterruptedJournalPhase` —— 写下
   `TARGET_REPLACING` + `TARGET_REPLACED`（已确认替换、账本未提交）；
2. **`adb shell am force-stop com.bd2toolsbox`** —— 真的杀掉进程；
3. `#verifyAfterRealRestartPhase` —— **新进程**从磁盘读回那条日志并分类；
4. `force-stop` + `#cleanupJournalPhase` —— 清干净（`finally` 一定会调）。

**判据是 PID 必须不同**：少了这条，就只是「同一个进程里自己写自己读」，
证明不了重启恢复。标记走 `sendStatus(REPORT_KEY_STREAMRESULT, code=2)`
（`Log.i`/`println` 回不到 `am instrument` 输出，实测过；code 用 2 而不是 0，
否则会把一次 phase 冒充成额外的 pass）。

### 2.3 实测

```
JournalRecovery [x86_64] 127.0.0.1:16384 -> PASS (write pid 10952 -> verify pid 10994)
```

`verify` 阶段断言：
- 必须读到上一条日志（`mine.size == 1`）；
- 必须判 `NeedsReconciliation`；
- **不得**被当成 `Committed`。

### 2.4 实现过程中踩到的两个坑（都是「假的验证」）

1. **`@Before` 里 `clear()`**：每个 phase 开始前都把 journal 清掉，于是
   `verify` 读到 0 条 —— 看起来像「重启后什么都没了」。
2. **`@After` 里 `clear()`**：写阶段写完，它自己的收尾又把日志擦了，
   `verify` 同样读到 0 条。

两次都表现为「重启后读到 0 条」。已改成：`@After` 只在非 phase 用例里清，
phase 用例显式把日志留给下一个进程（`keepJournalAfterTest`），只有 `cleanup` 清。

另外**把三条 phase 拆成独立的 `JournalRestartPhaseTest`**：它们要求 `-e bd2RunId`，
混在 `ProcessDeathRecoveryTest` 里会让那个类**整类跑不了**（实测 `FAILURES!!!`）。

## 2.5 隔离数据上的真实「装到一半被杀 → 重启 → 核对」

`Test-Bd2IsolatedRecovery`（`IsolatedCommitRecoveryPhaseTest`）：

1. `stageInterruptedCommitPhase` —— 在 `cacheDir/t25-isolated/<runId>/` 下建
   `staging/`（扮演下载/转换产物）与 `dest/`（扮演游戏目录，真实路径由
   `RecoveryObservationLayout.destFile` 按 `opId/bundle/hash/__data` 拼出）；
   **走生产 `ShizukuFileService.copyFile` → `AtomicFileWriter` 真的替换文件**，
   然后写 `TARGET_REPLACING` + `TARGET_REPLACED` 日志（带 `expectedContentSha256`
   与 `ledgerUpserts`），**刻意不写账本** —— 这就是那个窗口；
2. **`am force-stop`**；
3. `verifyIsolatedRecoveryAfterRestartPhase` —— 新进程断言四件事：
   - 分类必须是 `NeedsReconciliation`（不是 `Committed`）；
   - `TargetContentAudit` 必须是 `AllMatched`（文件**确实**换成了产物内容）；
   - 账本里**没有**那条记录（窗口是真的，重启后也不许凭空多出来）；
   - staging 文件**还在**（没有被自动清理），且隔离目录里**没有 `.part` 残留**；
4. `force-stop` + `cleanupIsolatedRecoveryPhase` —— 清日志 + 删隔离目录。

**全程只用 `context.cacheDir` 下的临时目录**，不碰真实游戏目录、MOD 源目录或备份。

```
IsolatedRecovery [x86_64] 127.0.0.1:16384 -> PASS (stage pid 11164 -> verify pid 11213)
```
