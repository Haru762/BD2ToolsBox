### 3.1 构建

### 3.2 动态资源访问追踪（本项核心）

- 收缩报告 `mapping/arm64Release/resources.txt` 含
  `android.content.res.Resources#getIdentifier present: true`。
- `dexdump -d` + `mapping.txt` 还原两处调用点：
  - `BoundsHelperApi28Impl` 查的是 **framework** 的 `navigation_bar_height`
    （不参与 app 资源收缩）；
  - **AboutLibraries** 查 `getIdentifier("aboutlibraries", "raw", <package>)` ——
    **这是真实的动态资源访问**。
- 应用自身代码 `rg getIdentifier app/src/main/java/` **零命中**。
- 因此加 `res/raw/keep.xml` 精确保留 `@raw/aboutlibraries`；不加它今天也不会被删
  （收缩器因检测到 `getIdentifier` 停在安全模式），加它是**不依赖该启发式**。
  实测加与不加的 APK 字节数相同，差别是显式 vs 凑巧。

### 3.3 必需资源仍在（机器可判）

python tools/audit_apk_size.py --apk …/app-arm64-release.apk --expected-abi arm64-v8a \

## 4. 测试发现并纠正的真实错误（文档层面）

T37/T38 断言「AboutLibraries 生成的 JSON **不内嵌**许可全文（实测 `licenseContent` 不存在），
全文由库内置 SPDX 映射运行时解析」。**实测字段名是 `licenses[<spdxId>].content`**
（不是 `licenseContent`），内容存在且完整（Apache-2.0 10,279 字符）。

这条错误有实际后果：如果按旧结论认为「全文来自 DEX、与资源无关」，
就不会给 `raw/aboutlibraries` 加保留，一旦收缩器换判定（AGP 8.12+ 新管线）就会
**静默丢全文**。已更正 `license-inventory.md` §3 与 `T38.md` §3。
