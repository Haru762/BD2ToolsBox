### 2.4 范围外偏差（**需要编排者裁决**）

`app/src/main/java/com/bd2toolsbox/ui/dialogs/AppDialogs.kt` 在 T05 声明的文件范围之外，
但**必须**改动才能编译：

```
- plan: MainViewModel.PrepackPlan?,
+ plan: PrepackPlan?,
- plan: MainViewModel.UninstallPlan?,
+ plan: UninstallPlan?,
- plan: MainViewModel.ConvertedOverwritePlan?,
+ plan: ConvertedOverwritePlan?,
（另加 3 行 import）
```

理由：验收要求「迁出 `MainViewModel` 内嵌类型」，而 Compose 侧按限定名 `MainViewModel.X` 引用；
Kotlin 1.9 **不支持嵌套 typealias**，data class 也不能被继承来保住嵌套名。改动是纯机械的
类型引用替换，函数体、参数名、UI 行为一律未动（`MainViewModel` 的 import 仍被
`MainViewModel.SHIZUKU_PACKAGE` 使用，未删）。

`AppDialogs.kt` 的归属模块是 T33/T55，不是 T06/T07/T10，因此不构成即时冲突。

`UninstallPlan.error` 从自定义 getter 改成**带幕后字段的 body property**
（`val error: String? = failure?.message`）也是被这个文件逼出来的。逼它的是
`AppDialogs.kt:261` 的 `Text(plan.error, textAlign = TextAlign.Center)`
与 `:285` 的 `plan.detail`：两处都在 `if (plan.error != null)` / `if (plan.detail != null)`
之后直接取值，**依赖智能转换**，而自定义 getter 会让 `Smart cast to 'String' is impossible`。
改 Kotlin 侧而不是改 Compose 侧，是为了把改动限制在最小面。

> 更正（独立复核查出）：本节初版写的是「Compose 里写的是
> `if (plan.error != null) { Text(plan.error!!) }` 形态的智能转换」——那句用了
> 「形态的」作限定，但读起来像引文，而 `AppDialogs.kt` 里**一个 `!!` 都没有**
> （`grep -c '!!' → 0`）。上面已换成逐字抄的两处真实写法。

**改动面精确到行**（便于 T33/T55 的复核者日后一眼确认没有别的东西搭车）：
新增 `AppDialogs.kt:46-48` 三行 import，加上 `:73`、`:227`、`:1573` 三处
`MainViewModel.X?` → `X?`。除这 6 行外 diff 为空——
没有函数体、没有参数名、没有 UI 行为变化。`:774` 仍在用
`MainViewModel.SHIZUKU_PACKAGE`，所以 `import …MainViewModel` 不是漏删。

## 6. 验收对照

### 6.1 「访问成功但为空」与「访问失败」是**不同类型**，调用方无法把后者当作空索引提交

- `DirectoryListingResult.Success(entries)` / `DirectoryListingResult.Failure(error)` 是两个
  data class，**没有公共父类型带列表**。
- 用例 `failureResultExposesNoEntryListAtAll` 用反射直接扫 `Failure` 的字段，断言它
  没有 `entries`/`items`/`list` 任何一个 —— 这是 API 形态的断言，不是调用方自觉。
- `successfulButEmptyListingIsSuccessWithNoEntries` 守住反向：`Success(emptyList())` 只表示
  「确实读到了且目录为空」，`isEmpty` 为 true 但仍是成功。
- `PagedDirectoryLister.list` 只有「成功且不足一页」才终止；`Failed` 一律是整次 `Failure`。

### 6.2 同 bundle 的多个 MOD 计划保留既有安装项；计划模型不依赖 UI 包和 Android 对象

- 合并逻辑迁到纯函数 `RepackPlanBuilder.build(selected, installed, availableByUri)`，
  输入输出全是领域值（`PlannedMod.modUri: String` / `targetHash` / `InstalledModRef`）。
- 用例：`sameBundleKeepsAlreadyInstalledModsAndPutsThemFirst`（并入且已装的排前）、
  `deduplicationIsByUriNeverByFamilyKey`（familyKey 相同的两个 mod 都在）、
  `installedModWhoseSourceIsGoneIsDroppedAndReported`（源文件不在 → 进 `droppedInstalled`；
  用例断言的是这个列表，**日志是调用方的事** —— `RepackPlanBuilder` 是纯函数，不记日志）、
  `installedModOnAnotherBundleIsNotPulledIn`、`selectedModThatIsAlsoInstalledAppearsExactlyOnce`、
  `emptySelectionProducesNoJobs`。
- 用例 `domainModelsReferenceNoAndroidOrUiTypes` 从 `core.model` / `core.fileaccess` 的 30 个
  入口类出发，递归扫描**字段类型、方法返回与参数类型、父类与接口**（含泛型实参、数组、
  kotlin 元数据类型），命中 `android.*` 或 `com.bd2toolsbox.ui.*` 即失败。
  这是「不依赖」的可执行判据，**不是**「按包封闭」的证明——边界逐条写在用例注释里：

  | 覆盖 | 不覆盖 |
  |---|---|
  | 自己声明的字段（含静态字段，即伴生对象属性） | **方法体内部** new 出来的 `Uri`（只扫签名） |
  | 方法签名（`copy` / `componentN` / getter 这些合成成员一并命中） | **顶层函数与顶层属性**（编译进 `…Kt` 类，没人引用就不入队） |
  | **父类与接口**（`class Foo : android.os.Parcelable` 会被抓到） | **ROOTS 是手写清单**：新增 core 类型忘了加、又没有 root 的签名指向它，就静默不扫 |

  其中「父类/接口」与「静态字段」两条是**第二轮补上的**（独立复核查出盲区），
  证伪实验见 §9.3：往 `RepackPlan` 的伴生对象塞一个 `android.net.Uri` 属性、
  再让一个接口 `: android.os.Parcelable`，两处都在一次运行里被点名。

### 6.3 三个操作是不同的操作

`OperationKind` 的 `SCAN_MOD_SOURCES("scan-mod-sources")` / `SCAN_GAME_INDEX("scan-game-index")` /
`PREPACK("prepack")` 各有独立的 id、阶段序列与可取消性；用例断言三者 id 稳定且互不相同，
阶段序列必须以 `QUEUED` 起、`COMPLETED` 收，且不含旁路终态。

**关于 `IncompleteScanException`**：没有另造平行异常，也**没有**新增任何异常类型。
本任务的错误是**结果值**（`OperationError`）而不是控制流；既有的
`ModRepository.IncompleteScanException`（`ModRepository.kt:79`）保持原样，将来由 adapter 侧
（T19/T23）翻译成 `OperationError(OperationErrorKind.MALFORMED_DATA, …)` —— 与它现在的语义
（分页被截断 / 文件夹没读完）一致，不需要第二套「可重试吗」的判断。

### 9.2 代码整改（3 处 + 1 处契约说明）

**(1) `buildRepackJobs` 的丢弃归因把两种原因算作一种**（`MainViewModel.kt`）

`availableByUri` 的口径是「源文件仍在**且当前解析得出 targetHash**」（`filter { !it.targetHash.isNullOrBlank() }`）。
于是 `RepackPlanBuilder` 查不到一个已装项时，可能是**两种完全不同的原因**：
源文件真没了，或者源文件还在但重扫后 targetHash 变空。

**归因错在哪一层，说清楚**：HEAD 的 `mergeWithInstalled` 就用 `byUri[uri] ?: … 源文件不在`
（`HEAD:1343` / `HEAD:1345-1348`）—— 「取不到就写源文件不在」这句话本身是**旧的**，不是 T05 发明的。
T05 改的是**取不到集合的口径**：一轮给 `byUri` 加了 `isNullOrBlank()` 过滤，
于是「源文件还在、只是重扫后解析不出 targetHash」这一类**新进入**被丢弃的集合，
却仍然沿用旧那句话。**是 T05 把这条日志变错的**，不是它继承了一个错。

改成分开归因（`byUri.containsKey` 区分两种原因），并且把 `availableByUri` 的口径写进
`OperationModels.kt` 的 `RepackPlanBuilder.build` KDoc —— **调用方会收紧契约**这件事
必须让下一位读这个函数的人看得到，否则他会以为 `null` 就是「源文件没了」。

`RepackPlanBuilder.build` 本身**没有改**：它 `availableByUri[ref.modUri]` 取不到就进
`dropped`，行为与一轮相同；二轮只让调用方说得更准。

**(2) `resolveModInfos` 丢弃时不吭声**（`MainViewModel.kt`）

一份**声明「丢弃必须说出来」，实现只记 `Log.w`** —— 用户看不见。
这一条我自己先写错过一次，如实记下来：我最初的理由是「`MainViewModel` 里没有
用户可见消息通道」，证据是 `grep '_toast\|snackbar\|_errorMessage'` 无命中。
**这个理由是错的**：同类里本来就有 `private fun toast(context, text)`（`MainViewModel.kt:3881`，
注释写着「Toast 统一走 application context」），本条与 (3) 都有现成的 `context` 参数。
正确做法不是找理由，是**用已有的通道**。

所以现在：`resolveModInfos` 只负责按 uri 反查、**不自作主张地报告**；
丢失的报告统一收在 `confirmConvertedOverwrite` 一处（日志 + `toast`），
避免两处各说一套。这条更正同时也说明：**「没有现成通道」是我没找就下的结论** ——
`grep` 的 pattern 里少了 `Toast.makeText`，而它就在同一个文件里。

**(3) `confirmConvertedOverwrite` 可能静默空操作**（`MainViewModel.kt`）

一轮的写法在「计划里的条目全部消失」时直接 `return`，用户看不到任何反应。
复核者给的原话是：**用户点了「仍要装入」，什么都没发生，也没有任何提示**。

现在分两种情形，都给出可见反馈：

- **全部丢失**：`Log.w` + `toast(context, "这些 mod 已不在当前列表（可能刚重扫过），本次装入已取消")`，
  然后 `return` —— 不装作装成功了。
- **部分丢失**：照样装（用户点的是「仍要装入」，不该因为少数条目失效就整个取消），
  但 `Log.w` + `toast(context, "有 $lost 个 mod 已不在当前列表，本次装入不含它们")` ——
  用户确认的是 N 个、实际装进去的是 N−lost 个，**差额必须当面说**，
  否则他会以为全装上了。

### 9.3 纯度用例的盲区与加固（这条是复核者查出来的，不是我）

复核者指出用例有三处**结构盲区**，其中两处今天就能被利用：

1. **父类 / 接口从不入队** —— 循环只把字段类型与方法签名的原始类入队，
   `cls.superclass` 与 `cls.interfaces` 从未入队。所以
   `class Foo : android.os.Parcelable` 这种「依赖挂在继承链上」的写法**一轮能通过**
   —— `Foo` 自己声明的字段和方法签名可以全是干净的。
2. **静态字段被 `Modifier.isStatic` 直接跳过** —— 伴生对象属性编译成外层类上的
   `static Companion` 字段，跳过它等于**整块伴生对象不在扫描面内**。
3. 方法体与顶层函数不扫（这条**没改**，理由见 §9.4）。

前两处已经关掉（`OperationContractTest.kt`）：父类与接口入队，静态字段不再跳过。
`INSTANCE` / `$VALUES` 入队无害 —— 要么已访问过，要么就是本类自己的数组。

**复核者先自己证伪了一遍**（这是它敢说「真闸门」的依据，不是我说的）：它给
