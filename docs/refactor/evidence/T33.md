## 2. 拆分结果

### 2.1 `MainActivity.kt` 1164 → 293 行

搬出去的根 UI 装配成为 `ui/AppRoot.kt`：主题、壁纸背景层、Scaffold、三个顶层页面、
全部弹层。需要 Android 系统的两件事通过接缝回调出去：

```kotlin
@Stable
class AppSystemHandoffs(
    val installUpdateApk: () -> Unit,   // 要 Activity 的 startActivity 与授权页
    val recheckShizuku: () -> Unit,     // 要 Toast 与 Shizuku 静态门面
)
```

其余原本用 `this` 的地方（16 处）都是 Context 用途，在 `AppRoot` 里用
`LocalContext.current` 即可 —— **不需要**把 Activity 传进去。

### 2.2 `ui/dialogs/AppDialogs.kt` 2134 行 → 6 个文件

| 文件 | 行数 | 内容 |
|---|---|---|
| `DialogCommon.kt` | 266 | 共用件：`dialogContainerColor` / `formatBytes` / `resetAndDismiss` / `MoveToGameSection` / `ShizukuGuideButtons` / `ManualInstallDetails` |
| `InstallDialogs.kt` | 761 | 预解包、装入、并行装入、解包工具、失败清单、转换覆盖、版本不匹配、扫描 |

| `SettingsDialogs.kt` | 259 | 备份管理、mod 源目录、丢失目录 |
| `UpdateDialogs.kt` | 201 | 更新、图片查看、更新就绪 |
| `PreviewDialogs.kt` | 78 | 预览进度、账本重置 |

共用件全部改成 `internal`（原来是 `private`，跨文件就不可见）。

### 2.3 落位偏离计划（登记）

计划把对话框放在 `feature/install/InstallDialogs.kt` 与 `feature/settings/SettingsDialogs.kt`。
**那会撞架构规则 R3（`feature/**` 不得 import `ui/**`）** —— 这些弹层依赖
`ui/` 里的共用件与 `ui/components`。所以落到 `ui/dialogs/` 下按 feature 分组，
与 T28 的 `ModRoute` 落到 `ui/screens` 是同一条理由。

### 3.1 `NavigationStateTest` 测了什么

| 用例 | 断言 |
|---|---|
| `tabSelectionIsExplicitAndFlat` | 三个 tab 平级，任意两个之间一步可达 |
| `settingsOverlaysAnyTabAndIsTheOnlyThingBackConsumes` | 没有盖层时**不**消费返回键；设置开着时消费一次并关掉，且不改当前 tab |
| `unknownSavedValuesFallBackToModsInsteadOfCrashing` | 存档来自旧版本 / 被改坏 → 回退 MODS，不崩 |
| `saverRoundTripKeepsTabAndSheetState` | `Saver` 往返保住 tab 与设置面板开合 |
| `tabSurvivesASimulatedRecreation` | **用 `StateRestorationTester` 真的走一遍保存/恢复** |
| `openSettingsSheetSurvivesASimulatedRecreation` | 同上，设置面板 |

用 `StateRestorationTester` 而不是真旋转：MIUI 上 instrumentation 起 Activity 会被拒，
且无头模拟器上真旋转不可靠；`StateRestorationTester` 走的是**同一套** SavedInstanceState。
