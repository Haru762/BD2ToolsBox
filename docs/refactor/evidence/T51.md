## 2. 原因（以本轮日志确认，不靠历史线索断言）

`Invoke-Bd2Gradle :app:stripArm64ReleaseDebugSymbols --rerun-tasks --info` 明确给出：

```
C/C++: android.ndkVersion from module build.gradle is [27.0.12077973]
C/C++: Folder D:\Android\Sdk\ndk\27.0.12077973 does not exist. Ignoring.
Unable to strip the following libraries, packaging them as they are: <11 个库>
```

AGP 8.11.1 默认 NDK 是 27.0.12077973，本机只装了 26.3.11579264 →
**strip 从未真正执行**，`libastcenc.so` 的 1.19 MB `.debug_*` 与 `libtexture2ddecoder.so`
的 164 KB `.symtab`/`.strtab` 全部原样进包。这是本轮之前**真实存在**的减包漏点。

## 4. 明确未完成（不勾 DONE 的原因）

- **arm64 真机未验**（`f7f409ac` 离线）：`lib/arm64-v8a/*.so` 的 dlopen 与 ASTC 解码
  只做了静态审计与 x86_64 设备验证。
- **`Test-Bd2ReleaseSmoke -Case 'native-load-and-decode'` 不存在**：该 case 未实现
  （`verification.ps1:1078` 只支持 `baseline-startup` / `snapshot-compatibility`），
  所以计划里的 release 包原生加载验证**未按计划命令执行**；本轮用
  x86_64 **debug flavor** 的设备用例代替，两者 `ndkVersion`/strip 配置相同但**不是**
  minified release 包。
- **ASTC 实际解码未在设备上跑**：只验证了库能加载 + 既有 BC1 解码路径；
  `libastcenc` 的 ASTC 解码入口未做端到端调用。
- **16 KB 页设备未验**：MuMu 是 4 KB 页；`libastcenc.so` 的 4 KB 链接对齐仍是
  登记在案的例外（独立于本项，见 native-strip.md §5）。
- 无独立审查。
