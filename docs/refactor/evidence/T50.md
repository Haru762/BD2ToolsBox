## 1. 审计输入（先看真实内容，再定清单）

`tools/audit_apk_size.py` 的嵌套 IMY 结果（`apk-before-arm64.json`）显示
`assets/chaquopy/app.imy` 里有 4 个 `.so`：

```
vendor/UnityPy/lib/FMOD/Linux/arm/libfmod.so      armeabi-v7a  1214580 B
vendor/UnityPy/lib/FMOD/Linux/arm64/libfmod.so    arm64-v8a    1254672 B
vendor/UnityPy/lib/FMOD/Linux/x86/libfmod.so      x86          1625248 B
vendor/UnityPy/lib/FMOD/Linux/x86_64/libfmod.so   x86_64       1569032 B
```

加上 `Darwin/libfmod.dylib`（2430928 B）与 `Windows/{x86,x64,arm}/fmod.dll`，
`vendor/UnityPy/lib/FMOD` 共 **18 个文件**。

## 2. 为什么整棵 FMOD 都与 Android 无关（逐条核对，不是按扩展名猜）

| 判定 | 依据 |
|---|---|
| macOS/Windows 不可用 | `UnityPy/export/AudioClipConverter.py: get_fmod_path()` 只在 `platform.system()` 为 `Darwin`/`Windows` 时返回这两条路径；Android 上是 `Linux`。Mach-O / PE 在 Android 上也加载不了。 |
| 桌面 Linux 不可用 | Android 上 `platform.system()=="Linux"`、`platform.machine()=="aarch64"` → 解析到 `Linux/arm64/libfmod.so`。但这是**桌面 glibc** 构建；Android 是 Bionic，且 UnityPy 未提供 `Android/<abi>` 构建。 |
| 根本没有调用路径 | `pyfmodex`（Python 绑定）**不在** `app/requirements-android.txt`（唯一 pip 清单，9 个直接依赖）。`import_pyfmodex()` 里的 `import pyfmodex` 必然 `ImportError`。 |
| 唯一使用点是桌面 CLI | 全仓 `extract_audioclip_samples` / `import_pyfmodex` 的调用者只有 `UnityPy/tools/extractor.py`（UnityPy 自带的桌面命令行工具）。应用自身的 Python（`repacker/`、`unpacker.py`、`resolver.py`、`main_script.py`）**没有任何**音频解码调用。 |
| 音频基线不变 | `extract_audioclip_samples` 对 Ogg/RIFF/m4a **按容器头直接返回字节**，不经过 FMOD；其余格式在本轮之前就已因缺 `pyfmodex` 而返回空。排除前后行为一致（设备用例断言）。 |

因此清单是 `vendor/UnityPy/lib/FMOD/{Darwin,Windows,Linux}` 三条**已核对路径**，
`lib/__init__.py`、`lib/README.MD`、`lib/FMOD/__init__.py` 一律保留 ——
不是「删所有 `.so`」，也不是「删整个 export 目录」。

## 3. 实现

- `config/android-python-excludes.json`：清单 + 每条的理由与证据。
- `tools/stage_android_python.py`：
  - `app/src/main/python` → `app/build/staged-python/main`；
  - **只读源**：源树一个字节不改（用例断言哈希不变）；
  - **确定性**：目标目录先 `rmtree` 再建；拷贝后 `os.utime` 把 mtime 归一为
    `FIXED_MTIME`（1980-01-01 UTC）；输出 JSON `sort_keys=True` 且**不含绝对路径**；
  - **清单防腐烂**：清单条目在源树里命中 0 个文件即 `StageLogicError` 失败退出；
  - 拒绝 `dest == source`、`dest` 在 `source` 内、`source` 在 `dest` 内；拒绝 `..` 路径与重复条目。
- `app/build.gradle.kts`：
  - 注册 `stageAndroidPython`（`Exec`，声明 `inputs.dir/file` 与 `outputs.dir/file`）；
  - `sourceSets.getByName("main")` 的 `python` 源目录**替换**（`setSrcDirs`）为暂存目录 ——
    替换而非追加，否则原树里的桌面二进制会被又带回包里；
  - 所有名字含 `Python` 的 Chaquopy 任务 `dependsOn(stageAndroidPython)`；
  - 构建机 Python 复用 `local.properties` 的 `chaquopy.python` → `CHAQUOPY_PYTHON` → `PATH`。
- 原 vendored 文件**保留在仓库**（`git status` 无删除），只在打包时剔除。

## 5. 明确未完成（不勾 DONE 的原因）

- **音频路径未做全格式回归**：只验证了 Ogg（不经过 FMOD）与 `pyfmodex` 不可用。
  UnityPy 的 FMOD 分支（`dump_samples`）在 Android 上**本来就是死的**，
  但没有对「所有音频格式」逐项跑一遍既有基线。
- **`Test-Bd2ReleaseSmoke -Case 'engine-and-preview'` 不存在**：该 case 未实现
  （`verification.ps1:1078` 只支持 `baseline-startup` / `snapshot-compatibility`），
  所以「release 包上」的引擎与预览回归**未按计划命令执行**；本轮用
  x86_64 **debug flavor** 的设备用例代替，两者共用同一份暂存源集，
  但**不是** minified release 包。
- **arm64 未跑**（真机离线）。
- **`app.imy` 之外的其它 IMY 未逐一核对**：本轮只改了源集暂存；
  `stdlib-*.imy` / `requirements-*.imy` 由 Chaquopy 生成，已由 `--expected-abi` 覆盖。
- 无独立审查。
